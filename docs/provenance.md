# Provenance

Where every part of huc6280-python came from, the licence of each source, and
a verdict, as audited on 2026-11-13 against local `main` `265df88` (provenance
audit, wave 1), with the verdicts updated on 2026-11-19 after the clean rewrite
([restart.md](restart.md)): each row keeps its 2026-11-13 verdict and adds what was
done. Verdicts: **clean** (our own work from facts or permissive
sources, cited), **cite** (clean, but a source must be named or a notice
kept), **rewrite** (derived from code we may not take, or a fact whose only
source is GPL code that was read), **unclear** (what would settle it is
stated).

## How this project used other emulators

Phase 0 (2026-10-23) pinned and read the source of MAME 0.285's `h6280`
(BSD-3-Clause), ares (ISC), Mesen2 (GPL-3.0), Mednafen 1.32.1 and the two
libretro beetle-pce trees (GPL-2.0), Geargrafx (GPL-3.0) and srg320's VHDL in
TurboGrafx16_MiSTer (recorded then as GPL-2.0+; unlicensed since Aubrey's verdict of 2026-11-24:
no LICENSE file at the pin and no notice on the HUC6280 files, so run only, fetched at the pin
and never committed); `scripts/pinned_repos.json` records each with
its licence, and the README says "the GPL and LGPL emulators named in these
documents are read, cited and run as referees". The family charter (rule 3)
now says their source is not opened while writing the code it would inform.
So every behaviour below whose only source is a GPL emulator's code is marked
for re-establishing by a closed-box run or a permissive or hardware source.
Where SingleStepTests huc6280 (MIT; generated by running Mesen) or a MAME
replay (closed box) already records the behaviour, that record is the
closed-box source and the item is clean once re-cited.

`provenance_check.py` was run against each pinned tree. Reading those trees
was this project's documented practice; I did not open them myself, only the
tool's report. Results:

| Reference | Licence | Hits |
| --- | --- | --- |
| Mesen2 `Core/PCE` | GPL-3.0 | opcode mnemonic rows (facts); **quoted source comments** in `docs/issues/0002`, `tests/test_directed.py`, `docs/timing.md` |
| beetle-pce | GPL-2.0 | `tools/mednafen-trace.patch` (now outside, in emu-tools-gpl2) context (expected; GPL tool); a **quoted comment** in `docs/timing.md` |
| beetle-pce-fast, Geargrafx | GPL-2.0, GPL-3.0 | none |
| TurboGrafx16_MiSTer | GPL-2.0+ as recorded then; unlicensed, run only, since 2026-11-24 | one mnemonic row (fact) |
| ares `huc6280` | ISC | mnemonic rows and opcode-number runs (facts) |
| MAME `h6280` | BSD-3-Clause | one register-name row (fact) |

`src/` has no hit against any tree.

## Closed-box sources removed (2026-11-24)

Aubrey's rule of 2026-11-24: an MIT repository does not download or keep the source of
anything the family's `sources.md` marks closed box only, unless a program with no shipped
build is built from it. Pins removed from `scripts/pinned_repos.json`, trees moved aside
unopened, out of the repository (not deleted): Mesen2
(https://github.com/SourMesen/Mesen2 @ `b9fa69ddc6d0a331fb103fdb5eef6904305703c2`, GPL-3.0),
Beetle PCE (https://github.com/libretro/beetle-pce-libretro @
`b96c11e095b6a40a412d2da02766ae1c3f4fd539`, GPL-2.0), Beetle PCE Fast
(https://github.com/libretro/beetle-pce-fast-libretro @
`4eee99c451f85ebe66d1591de88b892015b23059`, GPL-2.0) and Geargrafx
(https://github.com/drhelius/Geargrafx @ `57c257dda25f441fff3c63a63bbc4ba7cbb713e3`, GPL-3.0).

**Kept, with a question for Aubrey:** TurboGrafx16_MiSTer (`827d45f4`, unlicensed: run only),
because `scripts/build_referees.py` analyses its HuC6280 VHDL with GHDL for rung 5; and the
Mednafen 1.32.1 tarball with its unpacked tree under `reference/build/` (GPL-2.0), because
`scripts/build_mednafen.py` builds the traced detector from it with the emu-tools-gpl2 patch.
Neither has a shipped build that would do. Aubrey's answer (decisions page T3, 2026-11-25): both
move, one tool at a time. Mednafen moved on 2026-11-25 (below); the VHDL is still here.

### Mednafen's build moved to emu-tools-gpl2 (2026-11-25)

Decisions page T3: the traced Mednafen is now built by emu-tools-gpl2's `tools/mednafen`
(mednafen-build 0.1.0, GPL-2.0-only: `build.py --machine pce`, the same pinned tarball,
SHA-256 `de7eb94a...`, the same patch and configure options), and run from
`$EMU_TOOLS_GPL2/tools/mednafen/build/pce/bin/mednafen` (scripts/mednafen_trace.py, through
scripts/emu_tools.py; exit status 3 without it). `scripts/build_mednafen.py` now only runs that
tool's build as a program. The tarball's pin left `scripts/pinned_files.json`. Moved unopened to
a backup outside the repository (not deleted): `reference/build/mednafen-1.32.1.tar.xz`,
`reference/build/mednafen-src` (the unpacked, patched tree) and `reference/build/mednafen-bin`
(the program, sha1 `e70ac33f`). Identity check, 2026-11-25: `scripts/mednafen_trace.py` on
scripts/decimal_tables.py's own 8 KiB card (no commercial ROM), `--count 300000`, with the old
program and with the tool's: both traces 600,000 lines, 13,367,056 bytes, sha1 `fb30b743`, byte
for byte the same (OBSERVED; pcengine-python's `mednafen_record.py` gave the same file both ways).

**For review (a finding, not fixed here):** `scripts/compare_cycles.py`, `scripts/opcode_map.py`
and `scripts/manual_table.py` parse tables (cycle counts, opcode sizes, the opcode and
addressing-mode tables) out of the Geargrafx, Beetle PCE Fast and Mesen2 sources at run time,
and `opcode_map.py`'s `MODE_TEXT` spells Mesen2's addressing-mode names. A program reading GPL
source is still reading it (restart.md rule 1). They now stop with a message when the trees are
absent; the tables they printed on 2026-10-23 (docs/timing.md) are kept as recorded and marked.
Re-establishing them from Hudson's manual, MAME's BSD-3 `h6280.cpp` and SingleStepTests, or
retiring the scripts, is Aubrey's call.
