# Quirks (U) and contradictions between sources (C)

Each entry says what it is, the evidence, and the tier of that evidence
(validation.md defines them): **hw-verified** is an author's statement that
he ran it on a real console (MacDonald's pcetech: no ROM published, so it
cannot be re-run here), **manufacturer** is Hudson's manuals (scans, OCR read
by `pdftotext`; HW and SW as in start-here.md), **research** is other
documents, **emulator** is any emulator, the SingleStepTests corpus, or the
MiSTer VHDL. **A low tier detects and never judges**; where only emulators
speak, the entry is marked *undecidable here* and the build session picks the
majority behaviour and says so.

## Quirks (U)

| # | Quirk | Evidence | Tier |
| --- | --- | --- | --- |
| U1 | **Zero page is logical `$2000`-`$20FF`, the stack `$2100`-`$21FF`**, through MPR1 (usually $F8). Zero-page and stack accesses are never to logical page 0/1; software can read ROM through them | HW HB-3 (stack high byte $21); pcetech 2.0 | manufacturer, hw-verified |
| U2 | Reset: MPR7 = $00, MPR0-6 random; A, X, Y, S random; P has I and B set, T and D clear, N V Z C random; low speed; timer stopped, counter reads 0; interrupt disable register 0; `$FFFE`/`$FFFF` read from physical `$001FFE` | HW HB-18; pcetech 2.0 ("re-tested P startup value", "re-tested MPR startup value") | manufacturer, hw-verified |
| U3 | The 23 undefined/`NOP` opcodes are one-byte, two-cycle `NOP`s that change no register except to clear T; tested: $E2 $63 $33 $0B $2B $4B $6B $8B $AB $CB $EB $1B $3B $5B $7B $9B $BB $DB $FB $5C $DC $FC. The 65C02's multi-byte `NOP`s do not exist | pcetech 2.0 (the 23rd, $EA, is the documented `NOP`); the corpus has them at 2 cycles, 1 byte; MAME bills $63 four cycles (C4) | hw-verified |
| U4 | **T**: `SET` sets it; the next instruction's fetch clears it; only `ORA` `AND` `EOR` `ADC` use it (the operand pair becomes `M($2000 + X)` and the immediate/memory operand, result back to `M($2000 + X)`, A untouched, +3 cycles, flags from the result); `PHP` and `PLA` read T as 0, so does `BRK`; **an interrupt between `SET` and its target pushes T = 1 and `RTI` restores it, so the target is still affected**; `PLP` and `RTI` can set T from the stack (the next instruction is then affected "as if SET came before it"); `SED` before `SET` is the way to do BCD in memory because `SET` must be immediately before the ALU instruction (any other instruction clears T). With D = 1 and T = 1 `ADC` is 2 + 3 + 1 cycles | HW HB-5; SW `ADC` entry; pcetech 2.3; corpus (ADC # 638/635/621/606 cases at 2/3/5/6 cycles); `SBC` is C5 | manufacturer, hw-verified, emulator |
| U5 | **B**: reads 1 whenever P is read (PHP, `BRK`, PLA after PHP); the byte an IRQ or NMI pushes has B = 0; B in the corpus's P is always 0 (mask it) | HW HB-4; pcetech; corpus | manufacturer, hw-verified, emulator |
| U6 | **A block transfer cannot be interrupted**: the interrupt is taken when it ends. Whether the interrupt entry then comes before or after the next instruction fetch is not stated by anyone | pcetech; Mesen, MAME, Mednafen all run the block to its end (Mednafen's own comment, `huc6280.cpp`: "Needed so a BMT isn't interrupted") | hw-verified (for the claim), emulator (for the detail); detail *undecidable here* |
| U7 | A block transfer's **reads** of the hardware page from `$0800` to `$13FF` (PSG, timer, port) return **0** whatever is there, do not touch the device and do not change the I/O buffer; **writes** to them work and update the buffer; VDC and VCE are not in the range and work normally. This is CPU behaviour, so the core owns it | pcetech 2.0 | hw-verified. **MAME reads the real device here (C9)** |
| U8 | `(zp),Y`, `(zp,X)` and `(zp)` pointer reads wrap within the zero page (`$20FF` then `$2000`) in Mesen and MAME; the manuals do not say and no test covers a pointer at $FF | Mesen `ReadZeroPageWrap`; MAME `program_read16z` | emulator; *undecidable here* |
| U9 | `JMP (abs)` with the low byte $FF reads the high byte from the next page (`JMP [$FEFF]` reads $FF00): no NMOS wrap bug. Taking a branch across a 256- or 8192-byte boundary costs no extra cycle | pcetech 2.0 | hw-verified |
| U10 | `CSL` and `CSH` take 3 cycles when the speed does not change. **The cost of an actual change is unknown**, as is when the new speed takes effect (Mesen and Mednafen: for the last cycle of the instruction; MAME: after it). Reset selects low speed | pcetech 2.0 ("It currently isn't known"); C7 | hw-verified (the 3), the rest undecidable |
| U11 | `TAMi`/`TMAi` use an 8-bit **mask** operand (bit 0 = MPR0). `TAM` with several bits writes A into each; with operand $00 it writes nothing. `TMA` with operand $00 returns the last value moved by `TAM` (when at least one bit was set) or `TMA`; with several bits the result is "combined" in a way no one has worked out (C6). `TAM` is 5 cycles and `TMA` 4 | HW HB-7; SW; pcetech 2.0 | manufacturer, hw-verified |
| U12 | `ST0`/`ST1`/`ST2` write **physical** `$1FE000`, `$1FE002`, `$1FE003`: the address does not go through the MPRs, and the write reaches the VDC whatever MPR7 holds | HW HB-8 (Table 2-2-3); pcetech 2.0 | manufacturer, hw-verified |
| U13 | The last value read or written at `$0800`-`$17FF` sits in an 8-bit buffer; reads of PSG (`$0800`-`$0BFF`) return it in full, timer reads return it in bit 7, `$1400`/`$1401` return it in full, `$1402`/`$1403` in the upper five bits, the port returns none of it. Open-bus behaviour of the die | pcetech section 3 note 1, with its worked example | hw-verified |
| U14 | **Decimal mode**: `ADC`/`SBC` with D = 1 add one cycle, take the result from the BCD adjust, set N, Z, C from it and **leave V unchanged** | HW HB-4; SW; MAME changelog 1.08 ("Fixed the decimal version of ADC/SBC to *not* update the V flag") | manufacturer, emulator |
| U15 | `BRK` pushes `BRK + 2`, so the byte after it is skipped; B = 1; the vector is `$FFF6`, shared with IRQ2 | HW HB-4, HB-17; SW; pcetech | manufacturer, hw-verified |
| U16 | The timer: a 7-bit down counter ticking every 1024 x 3 master clocks, **independent of the CPU speed**; `$0C00` write sets the reload (N means N + 1 ticks), `$0C01` bit 0 starts it (stopped to started loads the counter from the reload); the request is raised when the counter **underflows from 0 to $7F**, and at once it reloads and keeps counting; `$0C00`/`$0C01` read the counter in bits 6-0 (bit 7 is the I/O buffer's); read it twice, the value can be invalid mid-update; writing any value to `$1403` acknowledges the timer, and an unacknowledged request interrupts again after every instruction | HW HB-20 to HB-22; pcetech 2.2 | manufacturer, hw-verified |
| U17 | The interrupt **disable register masks taking an interrupt, not requesting it**: `$1403` still shows IRQ1, IRQ2 and TIQ lines that `$1402` masks. IRQ1 and IRQ2 are level: they stay until the device is acknowledged (VDC: read its status register). NMI is not connected on any console | HW HB-15, HB-16; pcetech 2.1 | manufacturer, hw-verified |
| U18 | A **VDC or VCE access costs one extra cycle**, for any instruction and any addressing mode, including an opcode fetch from there; the CD-ROM registers in the same page do not | pcetech 3 note 3; MAME `check_vdc_vce_penalty`; Mednafen and Mesen2 | hw-verified, emulator |
| U19 | `BIT #imm` computes N and V from the immediate, unlike the 65C02 (where only Z is set); `TST`, `TSB`, `TRB`, `BIT` all load N from bit 7 and V from bit 6 of the **memory** operand | pcetech 2.0 ("`BIT #$C0` would set N and V"); HW HB-5; SW `TST` | hw-verified, manufacturer |
| U20 | `BSR` pushes the address of its last byte and takes 8 cycles; `JSR` 7; `RTS` and `RTI` 7. `RTI` pulls P first, then PCL and PCH | SW; corpus | manufacturer, emulator |
| U21 | The interrupt-disable flag changes after the poll: `CLI`, `SEI` and `PLP` delay their effect by one instruction, as on the 6502 (Mednafen samples I in `LastCycle` before the change). The same rule as the frame's `_polled_i` | Mednafen `IFlagSample`; HW HB-12 ("sampled in the last bus cycle") | emulator; undecidable here |
| U22 | The 65C02 additions with the same meaning as the Rockwell part: `PHX` `PHY` `PLX` `PLY` (the pulls set N and Z), `STZ`, `TRB`, `TSB`, `BRA`, `INC A`, `DEC A`, `(zp)`, `JMP (abs,X)`, `RMB`/`SMB`/`BBR`/`BBS`. `WAI` and `STP` do not exist | HW; SW; MAME changelog 1.08 (PLX, PLY flags) | manufacturer |

## Contradictions (C)

| # | The disagreement | Sources and tiers | Resolution proposed |
| --- | --- | --- | --- |
| C1 | `ST0`/`ST1`/`ST2`: 4 cycles or 5 | SW 4 (manufacturer); corpus 4; MAME and Geargrafx 5 (emulator, VDC stretch folded in) | 4 in the core, the +1 is U18 and the board's |
| C2 | `BRK`: 1 byte or 2 | SW and HW map: 1 byte (manufacturer); SW's own text, HW HB-17, pcetech: pushes `BRK + 2` (manufacturer, hw-verified); every emulator 2 | 2 (the manual contradicts itself; U15) |
| C3 | Interrupt entry: 7 or 8 cycles | MAME 7; Mesen, Mednafen, Geargrafx, ares 8 (emulator); no manual states it | 8 (four against one), flagged emulator-derived; *undecidable here* |
| C4 | `NOP` $63: 2 or 4 cycles | pcetech tested 2 (hw-verified); MAME 4; others 2 | 2; MAME's is an error |
| C5 | Does `SBC` honour T? | SW's `SBC` entry has no T clause (manufacturer); pcetech (hw-verified) lists ORA/AND/EOR/ADC only; Mesen, ares: no; MAME 1.10: yes ("Added T flag support to the SBC instruction") | no; MAME's is a guess |
| C6 | `TMA` with several mask bits | MAME: the highest set bit wins; Mesen: the OR of them; pcetech: "combined together... I have not figured out exactly how this works" | OR (a wired bus is likelier than a priority encoder, but this is reasoning, not evidence); *undecidable here* |
| C7 | When a `CSL`/`CSH` takes effect | Mednafen, Mesen: for the last cycle of the instruction; MAME: after it; pcetech: unknown | the last cycle; *undecidable here* |
| C8 | Position of the internal (no-bus) cycles and the address of every dummy read | Mesen/corpus is one model; Mednafen charges whole blocks of cycles with no model; manuals: totals only | the corpus's, flagged; a board sees them only through `idle` |
| C9 | Block-transfer reads of `$0800`-`$13FF` | pcetech: zero, no device effect (hw-verified); MAME and Mednafen read the device (emulator); Mesen unchecked | pcetech's (U7) |
| C10 | Timer vs VDC interrupt sampling | Mesen takes a pending VDC IRQ that became active in the next-to-last cycle but not a timer IRQ acknowledged in the last cycle of its `STA $1403` ("Order of the Griffon"); "Jackie Chan" and "Final Soldier" shake otherwise; Mesen's comment: "not tested on hardware" | the frame's rule (requests as of the next-to-last cycle) for every source; the timer's acknowledge is the board's to model; *undecidable here* |
| C11 | Which instruction fetch the interrupt follows | the HW manual says the interrupt is taken "when the instruction in progress is terminated"; MAME's changelog 1.10: "Taking of interrupts is delayed to respect a pending instruction already in the instruction pipeline; fixes After Burner" | the frame's one-instruction rule |
